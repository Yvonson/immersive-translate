# 功能机会调研与建议路线

日期：2026-10-18。代码基线：`f5b8bcb`。范围：当前独立项目的能力盘点、同类产品公开功能和技术可行性。

本文是研究建议，不代表用户已批准全部功能或开发排期。本轮不修改插件功能、版本、权限或数据处理方式。商业产品仅核对公开官方资料，未安装其当前版本逐屏测试；公开功能说明不能证明效果、价格或任意网站兼容性。

**后续状态说明（2026-10-22）：**本文保留 `f5b8bcb` 时的能力盘点，表中“生词收藏／复习／学习资料尚缺”等描述是历史基线。此后已交付生词本、快照、筛选、固定顺序翻卡、JSON 备份和 Alt+Q／Alt+S，见 [当前状态](../memory/STATUS.md)；Anki、间隔复习与视频学习侧栏仍是建议。正式 v0.2.0 已按 D-014 发布，D-008 预览冻结不再适用。完整演变与新对话入口见 [交接文档](../memory/HANDOFF-2026-10-22.md)。

## 1. 结论

最值得发展的方向是：**外语网页阅读、课程视频学习、本地词汇管理**。现有翻译、字幕和词典已经能为这三个场景提供基础。下一阶段优先让用户把看到的内容保存、理解和复习，再扩大文件格式及语音识别范围。

建议先补齐当前真实发音／网站验收，再优先做生词本、字幕精听、带搜索的文字稿侧栏、场景术语和导出。这些功能大多可以沿用已有文本、时间轴、词卡和模型接口，比重新增加一批翻译引擎更能改善日常使用。

## 5. 最建议先做的四组功能

### A. 生词本与 Anki／笔记导出：R-01、R-02、R-08

**实际使用**：在文章或字幕里查到 unfamiliar，点击收藏；以后看到该词可以查看当时的原句，复习或导出。

首版保存：选中的原词形、可得的原形、语言、选择的释义、上下文原句／已有译文、页面标题／来源、视频时间、标签和保存时间。只有主动收藏才保存，不把所有查词变成永久历史；无痕会话默认不落盘。来源地址应去掉不必要的跟踪参数与敏感查询参数，不保存课程 Cookie 或签名字幕 URL。

用户学习资料建议单独存入扩展 IndexedDB 等存储，与只读词库包分开，防止更新资源时覆盖收藏；预留版本迁移和 JSON 备份。

Anki 首版用 UTF-8 TSV 和稳定笔记 ID，明确字段映射；官方支持文本文件字段导入，因此不必先实现 `.apkg` 或安装连接插件。[Anki 文本导入说明](https://docs.ankiweb.net/manual/importing/text-files)

验收：网页／字幕收藏保留正确上下文；同词允许不同义项；重开浏览器、更新词库不丢失；导入导出保留内容与稳定 ID；词典数据与模型生成解释分别标来源。

### B. 视频学习侧栏与精听：R-03、R-04

首版侧栏提供双语文字稿、关键词搜索、当前句跟随、点击定位、字幕句内查词、收藏；播放器增加上一句／下一句、单句循环、句末暂停及隐藏／揭示译文。先针对现有已支持的文本轨做，不以“任意视频”作为首版完成标准。

**先决条件**：字幕叠加层当前 `pointer-events:none`，简单地把查词按钮塞进字幕并不能解决交互；应先设计侧栏内可选词的字幕文本，之后再研究不挡播放器操作的可交互叠加层。

已有 `cues`、播放器时间和轨道可以复用，但完整轨与仅当前字幕 DOM 必须分开：没有完整轨时显示能力降级，不伪造整段文字稿。切视频、切轨、关闭、广告／跳转、播放器被替换后都应停止旧循环和旧请求；字幕搜索不应自动触发整部视频的翻译。

浏览器原生侧栏需要 `sidePanel` 权限，API 从 Chrome 114 起可用，`open()` 从 116 起可用。当前最低版本是 111，可先采用页面内侧栏，或能力检测后再用原生侧栏，不能无提示提高版本要求。[Chrome 官方说明](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

验收：真实 YouTube／课程的暂停、跳转、切轨和换课；搜索命中跳转到正确 cue；循环不会在用户关闭后继续；全文搜索覆盖范围与实际已加载轨一致。

### C. 专业术语与上下文质量：R-05、R-10

AI 课程中的 `attention`、`embedding` 等应能由用户选择的词表约束。已有网页 `customDictionary` 占位符路径可以作为起点，升级为全局／网站／课程词表，处理大小写、多词短语、冲突优先级，并让字幕使用同一套术语。

当前模型请求的多字符串数组不等于完整文档上下文。可增加“当前段／当前句前后少量内容”的显式上下文输入，把上下文与待翻译条目分开，保持输出条数／顺序、格式标记和 cue 对应关系。

模型“看过邻句”不会自动解决所有术语和多音词。字幕句子合并需要保留原 cue 的开始／结束及映射，不用一个长译文覆盖多个时间点。增加或修改词表、场景或上下文设置后，应使相关缓存失效。

验收：同一课程术语在网页和字幕一致；代码／公式／专有名词不损坏；上下文不会成为要显示的额外译文；不能复现既有的相邻菜单／隐藏文字污染。

### D. 上下文解释与可追溯课程笔记：R-06、R-08

词典负责通用释义；显式的“解释本句”再调用用户选择的模型，给出本句词义、句法分解、习语及简明解释。技术内容还可以让用户选择“解释这个概念”，但不能把回答当作原视频讲师的原话。

先做选中句子的解释和用户收藏的笔记；全文摘要、章节问答必须建立在实际已取得的文本上，并能跳回对应句／时间位置。资料不足时说明不足，不仅凭视频标题生成课程笔记。回答带来源并不自动证明内容正确，需要校验支持关系。

## 6. 容易高估的能力与技术边界

1. **语音播放不等于可导出音频。** 浏览器语音不提供可通用复用的音频文件，不能承诺所有卡片都携带声音。先导出文字和读音资料；音频若以后提供，单独选用能返回音频的服务并核对其使用方式，不恢复真人录音批量下载。[Yomitan 的相关限制说明](https://yomitan.wiki/advanced/)
2. **原生视频画中画不会自动带上网页字幕叠加层。** Document PiP 可以承载 HTML，值得做原型，但要处理播放器生命周期、全屏、交互与兼容性；不能先承诺所有站点都支持。[Chrome Document PiP](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)
3. **本地模型接入不等于浏览器已有离线翻译。** Chrome Translator API 使用按需下载模型，需检测环境和语言对，桌面／移动支持不同；应先做扩展页运行环境原型，再决定是否接入，不自动下载模型。[Chrome Translator API](https://developer.chrome.com/docs/ai/translator-api)
4. **无字幕视频需要新增 ASR 链路。** `tabCapture` 需要用户触发和权限；捕获后还要保持原音频播放。Chrome 116 起支持在服务工作线程取流 ID 后交给离屏页消费；当前最低 111 需要兼容设计。[tabCapture 官方说明](https://developer.chrome.com/docs/extensions/reference/api/tabCapture)
5. **本地 ASR 仍有资源与延迟成本。** faster-whisper 是可评估的转写实现，但不是现成的任意网页实时字幕功能；还需要持续分块、去重、噪声处理、时间戳和设备基准。[项目文档](https://github.com/SYSTRAN/faster-whisper)
6. **PDF 阅读与保留原排版导出是两级工作。** 建议先可选中文本、再扫描 OCR、最后复杂重排。BabelDOC 提供 PDF 双语翻译库及 CLI／Python 接口，当前仓库标明 AGPL-3.0；如果研究集成，需单独核对其许可和依赖，不将其当作可以随意复制的前端组件。[BabelDOC 官方仓库](https://github.com/funstory-ai/BabelDOC)
7. **兼容词典格式不代表词库可随包分发。** 日语和第三方词典需要核验覆盖、版本及各自许可；先支持用户导入获准使用的词库，再逐项评估可分发资源。读音仍遵循用户选择的服务。
8. **输入框翻译需要预览和撤销。** 首版限定普通输入框／textarea，不触碰密码字段、不自动提交；contenteditable、ProseMirror 等富文本及输入法组合状态另做回归。

## 7. 建议开发顺序与暂缓范围

| 阶段 | 交付目标 | 进入下一阶段的依据 |
| --- | --- | --- |
| P0：补齐现有体验 | 真实英语发音、所选模型和重点站点回归；状态显示及错误诊断 | 有正常用户环境证据，不仅是模拟测试通过 |
| 第一组 | 字幕侧栏＋搜索／查词＋逐句精听；配套最小收藏和本地生词列表／JSON 导出 | 时间轴、切轨／换课及循环生命周期可靠；收藏保存稳定 |
| 第二组 | 完善生词本＋上下文整理＋Anki TSV／Markdown 导出 | 可备份、来源准确；没有隐性历史采集 |
| 第三组 | 场景词表＋跨片段语境＋显式 AI 解释 | 术语与时间映射一致；请求数量、输入范围和费用变化可见 |
| 后续按需求选择 | 生词高亮、输入框、OCR、PDF／EPUB、日语等 | 用户确实会反复使用，且已有模块能稳定复用 |

如果下一轮只选一个方向，建议先做**字幕学习侧栏＋逐句循环＋字幕内查词／收藏入口＋最小生词本**。理由是用户已经明确在 YouTube 和课程网站使用字幕，而仅能翻译已有文字稿还不足以支持复习与定位；先完成这条路径比同时增加 OCR、电子书和会议功能更容易验证实际收益。生词数据结构应在侧栏收藏入口前确定，避免先做按钮再重建存储。

暂缓完整口语打分、会议／直播 ASR、漫画自动擦字重排、完整桌面／移动客户端。它们需要不同输入、权限、算法及运维，不宜作为当前阅读插件的小改动。暂不把云账户、排行榜或自动多模型竞速加入核心范围；多引擎对照若以后提供，应由用户显式触发并展示额外请求。

研究当时正式版本字段遵循 D-008，本研究本身未创建版本标签或 Release；之后用户另行确认的正式发布采用 D-014。新增建议在用户选定后，再拆成开发计划、测试样本和验收标准。
